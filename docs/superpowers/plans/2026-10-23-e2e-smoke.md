# E2E e fumaça pós-deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Playwright joga uma rodada inteira contra um build local em toda PR, e confere produção em modo só-leitura depois de cada deploy.

**Architecture:** `@playwright/test` + `playwright.config.ts` (webServer local com PGlite quando não há `E2E_BASE_URL`); specs em `tests/e2e/`; helper `modo()` lê `E2E_SOMENTE_LEITURA`; `ci.yml` ganha os passos de e2e no job `verificar`; `deploy.yml` ganha o job `fumaca` depois de `deploy`.

**Tech Stack:** Playwright (Chromium), Next.js 16 `next start`, PGlite, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-23-e2e-smoke-design.md`

## Global Constraints
- Única dependência nova: `@playwright/test` (devDependency, versão exata mais recente estável com ≥ 2 semanas; `npm i -D @playwright/test@<versão>`). Scripts em `package.json`: `"e2e": "playwright test"`. Nada mais muda no manifesto.
- `playwright.config.ts`: `testDir: './tests/e2e'`; `use: { baseURL: process.env.E2E_BASE_URL ?? 'http://localhost:3100', viewport: { width: 390, height: 844 }, trace: 'on-first-retry' }`; `retries: process.env.CI ? 1 : 0`; `reporter: process.env.CI ? [['list'], ['github']] : 'list'`; `projects: [{ name: 'chromium', use: devices['Pixel 7'] ou chromium com o viewport acima }]`; `webServer` só se `!process.env.E2E_BASE_URL`: `{ command: 'npx next start -p 3100', url: 'http://localhost:3100', reuseExistingServer: !process.env.CI, env: { DATABASE_URL: 'file:.pglite-e2e', IP_HASH_SALT: 'e2e', NEXT_PUBLIC_SITE_URL: 'http://localhost:3100' }, timeout: 120_000 }`.
- `vitest.config.*`: garantir que `tests/e2e/**` não entra no `include` (ou `exclude`).
- Specs (`tests/e2e/jogo.spec.ts`): `somenteLeitura = process.env.E2E_SOMENTE_LEITURA === '1'`.
  1. "joga uma rodada inteira" (`test.skip(somenteLeitura)`): `/` → clicar `Começar` → esperar 8 `[data-casa]` → 8× (clicar botão `Verdade` → esperar painel com `Próxima` ou `Ver meu resultado` → clicar) → `[data-placar]` com texto `/^\d\/8$/` → botão `Compartilhar placar` visível.
  2. "abre o quiz e mostra o veredito da primeira carta" (sempre): `/quiz` → 8 `[data-casa]` → clicar `Verdade` → painel visível com `Próxima` → (fim; não avança).
  3. "páginas de resultado antigas e novas" (sempre): `/r/5-8-2-abre-o-olho-aaeaqaae` → 200, `[data-placar]` = `5/8`, botão `Começar`; `/r/4-12-3-caiu-feio-aeaqeeaeeqea` → 200, `4/12`; `/r/4-7-3-caiu-feio-aeaqeea` → 404.
  4. "imagens" (sempre, via `request`): `/cartao?a=5&t=8&c=2&f=abre-o-olho&g=aaeaqaae` → 200 `image/png`; `/opengraph-image` → 200 `image/png`.
  5. "API recusa corpo inválido" (sempre): `POST /api/resultado` `{}` → 400; `POST /api/evento` `{"tipo":"x"}` → 400.
  Rótulos exatos: `Começar`, `Verdade`, `Próxima`, `Ver meu resultado`, `Compartilhar placar` (ver `src/components/rotulos.ts`, `PainelVeredito.tsx`, `ResultadoFinal.tsx`, `src/app/page.tsx`).
- `ci.yml` job `verificar`, depois de `npm run build`: `npx playwright install --with-deps chromium` e `npm run e2e` (sem `E2E_BASE_URL`); `timeout-minutes` do job sobe para 20 se preciso. Cache do Playwright opcional (não obrigatório).
- `deploy.yml`: novo job `fumaca` com `needs: deploy`, `if: needs.deploy.result == 'success'`, `runs-on: ubuntu-latest`, `timeout-minutes: 10`, sem segredos: checkout (pinned, `persist-credentials: false`), setup-node (pinned, `.nvmrc`), `npm ci`, `npx playwright install --with-deps chromium`, `npm run e2e` com `E2E_BASE_URL: https://caiunessa.com.br` e `E2E_SOMENTE_LEITURA: '1'`. O job `deploy` precisa expor `outputs` só se necessário (não é: a URL é fixa). Manter `permissions: contents: read`. Passar `actionlint`/`zizmor` (CI já roda).
- `.gitignore`: `.pglite-e2e/`, `/playwright-report/`, `/test-results/`.
- Rulings do controlador (depois da checagem de construtor): a primeira rodada tem **8** cartas (`tamanhoDa` = 2 lados × soma; conferido em produção); o spec importa `TOTAL_AFIRMACOES` de `../../src/lib/rodadas` em vez de escrever 8 (regex `new RegExp(`^\\d+/${TOTAL_AFIRMACOES}$`)`, `[data-casa]` count = `TOTAL_AFIRMACOES`). Os botões de resposta existem de verdade (`Quiz.tsx`, `aria-label` de `ARIA_BOTAO_RESPOSTA`, texto `Verdade`/`Mentira`/`Cheira mal`); use `getByRole('button', { name: /verdade/i })`. Carregar `/quiz` e responder cartas não grava nada (o POST é só no fim); conferido. `next start` com `DATABASE_URL=file:` funciona num build de produção (conferido: quiz 200, evento 204, cartao/og image/png, /r 200). Os códigos `/r` do plano são válidos (conferidos em produção). O job `fumaca` começa com um passo de espera: até 12 tentativas, 10 s entre elas, até `GET https://caiunessa.com.br/` responder 200 (`curl -sf`), para não acusar erro enquanto o alias propaga. E2E fica dentro do job `verificar` depois do build (reusa `.next`); o gate `ci` não muda. Limite de 5 jogadas/min por IP em `/api/resultado` não atrapalha (1 jogada por execução).
- Commits sem `JUL-`; trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus
1. Modo só-leitura nunca termina uma rodada nem toca em compartilhar (não grava em produção). Spec 2 + `test.skip`.
2. O e2e local falha se "Começar" sumir (defeito proposital, conferido pelo controlador).
3. `webServer` não é definido quando `E2E_BASE_URL` existe (senão o job de fumaça tentaria subir um servidor).
4. Vitest não tenta rodar `tests/e2e`.
5. `zizmor`/`actionlint` verdes nos dois workflows.
