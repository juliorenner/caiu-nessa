# Rodadas (pool único, sorteio, "Continuar jogando") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every visit draws a balanced round of 12 from the whole statement pool, and the result screen offers extra balanced rounds of 6 until the pool runs out.

**Architecture:** One data file is the pool; `sortearRodada` draws N per (lado, veredito) pair excluding seen ids. The result API accepts any balanced round (12 or 6) of pool ids and scores it; statistics rank only 12-rounds and measure "% erraram" per statement by appearances. A new `POST /api/rodada` draws the next round; a client `Partida` component accumulates seen ids and the running score and remounts `Quiz` per round.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript 7, Zod 4, Drizzle (neon-http / PGlite), Vitest + Testing Library. No schema migration (`jogadas.total` already exists).

**Spec:** `docs/superpowers/specs/2026-10-22-rodadas-design.md`

## Global Constraints

- Neutrality per round: same count per lado and, within a lado, per veredito. First round 2 per pair (12), extra rounds 1 per pair (6). Nothing unbalanced is drawn or accepted.
- `lado` never reaches the client; drawn rounds are shuffled and stripped server-side.
- Pool minimum: at least 2 playable statements per (lado, veredito) pair, or the data test fails.
- Copy in pt-BR exactly as the spec writes it; `JUL-` ids never in commit messages or PR text.
- All text ≥ 16 px; the quiz screen keeps the v2 layout rules.
- No cookies, no persistence of seen ids across visits.

## Review Focus

1. A request to `/api/resultado` with 12 valid pool ids that are not balanced (e.g. 3 falsas de um lado) must be 400, not scored. (Task 2 test.)
2. A request with 6 ids where one id has `observacao` (fora do jogo) must be 400. (Task 2 test.)
3. `sortearRodada` with `excluir` leaving exactly 1 item in a pair and `porPar = 2` returns null, never a short round. (Task 3 test.)
4. The player who presses "Continuar jogando" twice quickly gets one request, not two rounds. (Task 5 test.)
5. "% das pessoas erraram esta" for a statement seen in fewer than 30 games is absent (sheet shows no line), not 0%. (Task 2 test.)
